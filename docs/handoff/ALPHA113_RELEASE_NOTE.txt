alpha113: a crash fixed, and a better look inside claude.ai (alpha112 is inside this build). WHAT THE NEW RECORDING AND DIAGNOSTICS SHOWED: (1) alpha112's change worked where it should. In your second recording of claude.ai the main thread's queue for the script files is about a third shorter: a file now waits about 5 seconds from open to end instead of 8, and the messages through the blocker fell from 2,665 to 1,047. The page itself still needs 11 to 18 seconds to a first paint, and the reason is hidden again: the page's own process ran out of memory while writing its part of the recording, exactly as the first time. (2) A CRASH in the keep-the-page-ready feature, found in your Diagnostics: if you leave Kestrel and come back within a moment, Android 8 to 11 can close the app with the message that a service did not call startForeground. It ended one run of alpha111 that way. WHAT CHANGED: (1) The crash is fixed: the hold is only stopped after Android has really started it, and a hold that has not started yet ends itself right after it has. (2) Record a profile of this page is kinder to the page process: one thread instead of four, 20 seconds, and 2.5 seconds before the end Kestrel tells the engine to give memory back so the page process has room to write its part. The recording also tells you at once, in a message, if the page itself is missing from it. (3) The profile reader can now name the engine's own functions: it asks Mozilla's public symbol service, sending only the library name, its build id and offsets inside it, nothing about you, a page or a file. It showed that Kestrel's own blocker code is under 1 percent of the main thread, and Firefox's own hand-over around it is about a fifth. (4) The diagnostics reader no longer counts swiping the app away from the recent apps as a memory kill.
