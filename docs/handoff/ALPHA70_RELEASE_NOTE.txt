alpha70: your messages after alpha69 (the doraby crash, and the video rows that disappear). (1) THE CRASH ON DORABY: you told me the app just vanished to the home screen, so it was not a freeze. My own code only ends the app when it has nothing left to do, and it records that, so Android or the engine ended it from outside. I cannot say which yet: your Diagnostics showed no crash note, no engine crash report and about 1 GB of memory free, but the free-memory number does not count what video decoders and the five engine processes hold on a 2 GB tablet. So this release records the real evidence: every 15 seconds while the app is in front, and at every notable event, the note on disk now holds the memory of each part of the app (main, page, graphics, media), the system free memory and swap, and the kernel memory pressure when the tablet has it. Diagnostics line Last run then says, for the run that ended, how much memory the app held at its last moment and whether memory was low (Android memory killer) or fine (a crash that left no report). It also keeps the last three runs that ended badly instead of one, keeps the freeze lines if the screen ever hangs, and writes its note from its own thread so a hang cannot silence it. If the app vanishes again, open Menu then Diagnostics as soon as it is back and send me the text. (2) VIDEO ROWS NO LONGER DISAPPEAR: once Kestrel has read a stream and it runs 2 minutes or more (or a file is 40 MB or more, or you opened it), it is kept in the list when the player frame reloads or goes away, and when the same page loads again; it moves to the end of the list and is replaced only when another player offers a film of its own, or when you go to another page or another episode. Short clips, previews and advertisements are still hidden as before. (3) THE FINDER ASKS MORE POLITELY: when a video server answered 404 to the first way of asking (some servers do that instead of 403 when they dislike the request), Kestrel now tries up to two other ways, and it no longer asks again for page requests that were not plain reads. NOT proven on the tablet: that the rows stay on the real doraby servers; vidsrc and 111movies themselves are NOT solved: I do not yet know why their players are not found. Please open one of them, wait until it plays, and send Diagnostics right then: the media lines (maybe, maybe-refused, maybe-hit, frame-gone, page-clear) show what Kestrel saw. Checked with tests and on a simulated Android tablet with the real Firefox engine, using test pages that behave like those sites.
