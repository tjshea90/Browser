alpha112: the first real look inside a page load, and a first fix (alpha110 and alpha111 are inside this build). WHAT THE RECORDING SHOWED: the recording of claude.ai you sent was read the same hour. It holds the main process only: the page process ran out of memory while it handed over its part, so this build records a shorter window to try again. The main process half is already clear. claude.ai asks for about 1,250 script files in one burst at load, all from the disk cache, and every one of them must pass through the main process thread, which is also where Kestrel's blocker runs. For about 15 seconds that thread is completely full, and each request waits roughly 8 seconds in the queue, whether the file is 139 bytes or 300 KB. Firefox's own hand-over of each request to the blocker and back costs about a third of that busy time; Kestrel's own blocker code is about 1 percent of it. WHAT CHANGED: (1) The blocker's second listener, which only counted finished requests for the Diagnostics, now ignores the page's scripts, pictures and fonts and watches only pages, frames, style sheets and fetch calls. On your recording that removes 1,326 of 2,665 messages through the main thread, about half of the blocker's per-request work. Expected: claude.ai reaches its first paint a few seconds sooner (an estimate, not measured). Files that fail to load are still reported for every kind of file; the Diagnostics lose only the cache and 304 counts, and the 404 or 500 answers, of scripts, pictures and fonts. (2) The profile reader now joins start and end rows, counts each request once, and prints how long requests wait for the blocker, so the next recording answers the next question. (3) Record a profile of this page now records the first 22 seconds of the load (fewer threads, a smaller recording) and says so.
