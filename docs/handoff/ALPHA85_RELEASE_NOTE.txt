alpha85: the live diagnostics now explain WHY a page is slow, which you asked for after Claude.ai and YouTube felt slow even on fast Wi-Fi. What the tablet's own numbers already said: a Claude.ai load took 28 to 35 seconds, in one earlier visit about nine in ten of its requests (over a thousand) came from the cache, so the link is probably not what is slow; the ad blocker costs about 1.6 milliseconds per request, which would be roughly 6 percent of a thousand-request load, so it is probably not the main cause either. What was missing was where the rest goes, so each page load now sends one small scrubbed line from the page itself: time to the first byte, first and largest paint, how many requests and how many were slow, which hosts were slowest (names only, never an address path), and how long the page was too busy to answer, which tells a page busy with its own scripts from one that is waiting for the network. Also sent now as numbers instead of cut-off text: the blocker's cost, processor use of the browser and of the page engine, memory of every process, start-up times and slow-frame counts. The suggestions in Settings, Live diagnostics, now say when a slow site is busy with its own scripts (a faster link will not help) or when the blocker is a large part of its load. Claude reads all of it with one command and sorts every slow site into busy, waiting or blocker-heavy. Nothing about the engine settings was changed because the cause is not proven yet; after a day of normal browsing the next files will name it. Same privacy as before: only your private repository, only your token, never a private tab, sensitive sites never named, and the master switch off means nothing is recorded, kept or sent. NOT run on the tablet: the new timing has only been tested in a desktop browser.
