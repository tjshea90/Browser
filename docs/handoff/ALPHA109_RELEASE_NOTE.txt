alpha109: cut-off pictures and text, found in your diagnostics. WHAT THE UPLOADS SHOWED: the upload you sent tonight (alpha108) says Kestrel was drawing pages on the graphics chip with every engine drawing shortcut at its default: Safe drawing was off, Software drawing was off and the hardware trial was off. That is the mode that cut bands of text and pictures in alpha89 to alpha91 and the only one of the three that never drew cleanly on this tablet. Hardware trial 1 (the Mali fixes) was on in the alpha107 upload with Safe drawing on, so tonight's report does not show that trial 1 itself cuts text. A trial that switches itself off used to fall back into the same mode, which is how it can happen without anyone choosing it. WHAT CHANGED: (1) That mode cannot be reached any more. The shortcut switches are always turned off while the graphics chip draws, and the Safe drawing switch is gone from Settings. (2) Settings has ONE choice, How pages are drawn: the processor (slower, never leaves a part undrawn) or the graphics chip with fixes (smoother, still being tested). A tablet found in the old plain mode is moved to the graphics chip with fixes at the next start and Settings says so. (3) If the graphics chip stops drawing steadily or the page process crashes early, Kestrel now falls back to the processor, not to the failing mode. (4) New menu tile, Parts of the page are missing: one tap notes it with the drawing mode in force and redraws the screen; a second tap within 3 days switches Kestrel to the processor by itself from the next start. (5) The diagnostics digest now prints a DRAWING section: the mode of every upload and the taps per mode, so the next review can say which mode lost a part. NOT RUN on your tablet: this build, the move out of the plain mode, the fall back to the processor and the new menu tile (the emulator draws with the processor and has no Mali chip). STILL OPEN: if you still see cut-off parts with the graphics chip with fixes, tap the new tile when it happens; two taps and Kestrel moves to the processor on its own.
