| V1 | core/.../media/StreamEngine.kt:828, 836, 1079-1087, 1049, 642-646, 971; Hls.kt:165 | The first playlist read and every AES key fetch have NO retry: a hiccup fails the job or wipes it. Choose 720p on a master playlist: only the probe (lowest-bandwidth) variant arrives with its text, every other variant and every separate-audio rendition starts with `readText`; one connect timeout / reset / DNS blip / 5xx / 429 / 408 fails the job. Cause: `val resp = open(job, fetcher, FetchRequest(...))` sits outside the `try`; `FetchException` extends Exception, not IOException, so `catch (e: IOException)` misses it; `Retry` (from `statusFailure`) is a RuntimeException; both land in `catch (e: Throwable)` and the row shows Reason.STORAGE "Could not write the file". `keyBytes` has the same shape. Where the MP4 writer is on, `appendNext` turns any RuntimeException into `MuxBroken`, which wipes the staging and restarts the whole download as a raw .ts. Second problem: Hls.kt:165 adds a `Key` for every `#EXT-X-KEY` tag; a playlist repeating the tag before each segment = one serial key request per segment, inside `appendNext` under the drain lock, each fatal on failure. Fix: fetch playlist + keys with the machinery `fetchTo` already has (retries, header ladder, outage handling), e.g. `fetchTo(job, fetcher, url, -1, -1, File(dir, "key$ki.bin"), false)` then read 16 bytes; cache `job.keys` by key URL, not by tag index; prefetch every distinct key URL in `prepare`; catch FetchException in `readText`. | OPEN |
| V2 | StreamEngine.kt:1249-1253, 1271; GeckoFetcher.kt:24 (windowBytes = 4 MiB) | A server that IGNORES RANGE silently cuts each segment at the window size: a 6 MB 1080p segment on a PHP / worker proxy that answers 200 to `Range: bytes=0-4194303`: `var limit = if (whole && rt >= 0) rt - maxOf(rf, 0L) + 1 else Long.MAX_VALUE` stops the body after the window, then `if (whole \|\| rf < 0) return` treats the segment as complete; the 4 MiB .seg is renamed, appended and shown as a finished video with no error. Fix: for a 200 reply take the whole body when the segment length is unknown (`limit = MAX`); only when the length is known (BYTERANGE) use `skip = from`, `limit = toInclusive - from + 1` over the whole sub-range, not the window. | OPEN |
| N1 | core/.../media/EpisodeNames.kt:181-182 | The title cleaner keeps ONLY the first " - " or " \| " part: `var s = (if (last) segments.lastOrNull() else segments.firstOrNull()) ?: return ""`. "Rick Astley - Never Gonna Give You Up (Official Music Video) - YouTube" splits into [Rick Astley, Never Gonna..., YouTube]; "YouTube" is dropped as the site; file = "Rick Astley - 720p.mp4", expected "Rick Astley - Never Gonna Give You Up (Official Music Video) - 720p.mp4". "Mission: Impossible - Fallout (2018) - Site" becomes "Mission - Impossible - 720p". Rule: drop only segments that ARE the site (equal to the host label or og:site_name, a bare domain, noise-only); keep the rest joined by " - " (up to three); also drop a trailing segment of three words or fewer that repeats on other pages of the host; send og:site_name from names.js; prefer og:title / JSON-LD name over document.title (N3). | OPEN |
