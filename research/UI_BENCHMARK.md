# Kestrel UI benchmark and design direction (task R1) - researched 2026-11-11
Method: web search/fetch only. No emulator, no screenshots: every visual judgement below is text-based and must be re-checked on emulator screenshots (task C4) and on the tablet.
Tags: [V] read in a fetched primary page; [S] search snippet only (page blocked or empty); [U] my inference/knowledge, unverified. Units are dp (tablet: 564x916 portrait, 916x564 landscape, density 1.0625).

## 1. Decisions (read this first)
1. **Choose the chrome layout at RUNTIME from window dp, never with `sw600dp` resources.** The tablet is sw564, so `sw600dp` never matches, and Chrome/Brave (tablet = sw600dp, `DeviceFormFactor` [V]) show their PHONE layout on it:
   the owner's "Brave look" is Brave's phone layout (address bar on top, no tab strip, optional bottom toolbar [S]). Window size classes: portrait = compact width (<600) + expanded height (>=900); landscape = expanded width (>=840) + medium height [V].
2. **Touch targets: 56 dp default, 64 dp for the bottom-bar cells and the Tabs/Menu buttons, 48 dp is an absolute floor** (secondary only: card close, row-end buttons). On this ~170 ppi panel 48 dp = 7.6 mm, 56 = 8.9 mm, 64 = 10.2 mm (section 2).
3. **Portrait = SPLIT chrome**: address row on top (56) + action bar at the bottom (64: Back, Forward, New tab, Tabs, Menu). **Landscape/wide = UNIFIED** single 56 dp row + a 48 dp tab strip when >= 2 tabs. Precedent: Vivaldi moves the bottom icons to the top bar on large screens [V].
4. **Tabs**: portrait has no strip (tab-count button -> full-screen 2-column card grid, swipe on the address field to switch [U]); landscape has the strip (close button on the ACTIVE tab only, as Chrome hides it on narrow tabs [V]) plus the same grid. Setting "Tab bar: Auto / Always / Never".
5. **Address field** = one big target (548 dp wide in portrait): lock/state cell, host in bold, Shields chip (the only yellow block in the chrome), reload/stop 48. Typing = chrome hides, an OPAQUE suggestion layer covers the page (no page relayout while the keyboard is up).
6. **Menu** = 4x2 tile grid (Reload, Bookmark, Share, Find, Desktop site, Text size, Save data, Print) + 5 list rows (Private window, Bookmarks, History, Downloads, Settings) + Quit; bottom sheet in portrait, right panel in landscape. All rows 56.
7. **Shields panel**: master switch + honest counts, "Advanced controls" accordion collapsed by default (Brave's mental model [V]); one panel for lock + Shields (no separate site-info popup).
8. **Visual identity "CERE"** (alternatives RUFOUS, STOOP in section 7): cool slate neutrals that follow the system light/dark theme, ONE accent = cere yellow `#F6C026` used only for "armed / selected / found / under your finger", flat surfaces with 2 dp rules (no shadows), 6 dp control radius, a single 8 dp top-right chamfer on "object" containers, mitred 2 dp icons, system fonts only.
9. **No animation, by construction**: zero-duration `StateListDrawable`s instead of `RippleDrawable`, custom 2-state toggle instead of `Switch`, `PopupWindow.setAnimationStyle(0)` [V], dialog/window animations null, no overscroll glow, no Toast/Snackbar (own instant bar). Because nothing moves, state must be WORDS + fixed geometry (ON/OFF text, never reflow buttons).
10. **Keep the tokens swappable** (`Pal` -> one `Tokens` table) so the owner can A/B concepts in one APK; ship CERE as the default.
11. **Leave out**: news/feed, AI, rewards, wallet, VPN, sync, Tor, telemetry, sponsored tiles/wallpapers, shopping, Lens, cast, translate, payment autofill, promo/"what's new"/rate-us dialogs (section 5).
Owner decisions needed (recommendation first): (a) split chrome with a bottom bar vs everything on top [setting provided]; (b) CERE vs the safer RUFOUS; (c) landscape tab strip (recommended, familiar) vs a 56 dp left tab rail (fresher, saves 48 dp height, unusual on Android - not recommended without a trial).

| 2 GB / Mali-G52 MC2, 0.58 MP screen | Android says low-end GPUs have low-res screens, so optimise UI-thread work first; still avoid shadows/alpha/nested backgrounds [V overdraw page] |
Guideline numbers relied on: Android >= 48x48 dp targets, >= 8 dp apart, "about 9 mm", "recommended 7-10 mm" [V]; WCAG 2.2 AA 24x24 CSS px (2.5.8) and AAA 44x44 (2.5.5) [V];
Microsoft 7.5 mm (current) / 9 mm ideal (older Windows Phone docs) [V/S]; Parhi et al. 2006 one-thumb study: 9.2 mm discrete, 9.6 mm serial [S abstract]; NN/g >= 1 cm and ~2 mm spacing [V].
Note: 1 dp = 1/160 in = 0.159 mm, so 48 dp = 7.6 mm although Android's page says ~9 mm; 48 is therefore the FLOOR here, not the target. Hoober's grip study covers phones only (49% one-handed, 36% cradled, 15% two-handed), tablets were not measured [V] -> tablet ergonomics are [U].
Spacing: toolbar cells abut (each cell is a full 56x56 or 113x64 target); isolated small targets keep >= 12 dp (~1.9 mm); destructive vs safe actions >= 16 dp apart.

|                                    |           |                 page 436 dp (81%)                        |
+------------------------------------+           +----------------------------------------------------------+
| [<]   [>]   [+]   [3]   [=]        | 64 (5 x 113 dp) + gesture inset

`ChromeMode.of(widthDp, heightDp)`: SPLIT if width < 600 and height >= 700; UNIFIED otherwise; strip if width >= 840 and tabs >= 2 (or setting); no strip if height < 480 (split-screen). Re-run on `onConfigurationChanged`.
Rows/children: toolbar is a vertical `LinearLayout` [strip][row][progress][engine view weight 1][bottom bar] - siblings, never overlays on the engine view. Landscape field = 564 dp (916 - 6x56 - 16); portrait all-top fallback field = 388 dp.
Disabled Back/Forward stay visible in muted colour (stable geometry). While typing the bottom bar is GONE (not resized). Optional "Hide status bar in landscape" (+24 dp). No auto-hide-on-scroll in v1: it resizes the engine view (reflow on a slow SoC) and would animate.

## 4. Behaviour specs
**Address field** (48 tall in the 56 row, 6 dp radius, white / `field` fill with a 2 dp outline): idle shows host bold 17 sp + path muted 15 sp (https scheme and "www." hidden, as today); http shows the word "NOT SECURE" in danger colour; offline shows "SAVED COPY".
Tap -> full URL, select-all, keyboard (`IME_FLAG_NO_EXTRACT_UI`, private: no personalised learning). Long-press -> Paste & go / Copy / Share. Lock cell and Shields chip both open the one Shields panel.
**Typing mode** (keyboard open): field spans the row with clear (X, 48) and Go; every other chrome button is hidden; below it an opaque layer (rows 56: "Search Google for ..." first, then <= 6 local history/bookmark matches, each with a 48 dp "fill" arrow). Rows fit = floor((892 - 56 - keyboard)/56): ~9 portrait, ~4 landscape (keyboard 280/230 dp assumed [U], measure on device). Use `SOFT_INPUT_ADJUST_NOTHING` while the field has focus so the engine view never resizes (pairs with R6 freeze work [U]).
**Tab strip** (landscape): tabs min 128 / max 220 wide, 48 tall, favicon-or-letter 20 + title 14 sp; active tab = chrome fill + 3 dp yellow top rule + chamfer + the only close X (48x48); "+" 48x48 after the last tab; long-press tab = Close / Close others / Duplicate. 7 tabs fit at 123 dp, then it scrolls.
**Tab grid**: header 56 [X][N tabs][New tab = yellow primary][overflow: Close all]; cards portrait 2 cols x 264 dp, landscape 3 x 289 dp, gutter 12; card = header 48 (letter tile 24, host bold, close 48x48) + body 112 (title 2 lines, host, age); current tab: 3 dp yellow frame + word "OPEN". No thumbnails in v1 (optional later: 280x160 px RGB_565 = ~89 KB each, 20 tabs = 1.7 MB, kept on disk). Close = instant + an "Undo" bar for 6 s.
**Menu**: tiles 72 tall, label 13 sp; list rows 56; "Close all tabs" lives in the grid overflow, Quit is last and confirms only if downloads are active. Landscape right panel 360 wide, scrolls.
**Shields panel** (anchored under the chip, 360 wide, <= 548 portrait): row 1 host + big ON/OFF block (56); row 2 readout "N blocked on this page" (24 sp condensed) with a tap-to-expand list of top blocked hosts (Brave does the same [V]); "Advanced controls" (collapsed): ads/trackers, cosmetic, HTTPS, cross-site cookies, fingerprinting, scripts - 56 rows, ON/OFF words; footer "Changes reload the page". Only counts the engine truly measures; no estimates (Brave's NTP "data/time saved" are estimates [S]).
**New tab page**: wordmark 28 sp + search field 56; favourites 4x2 tiles (133x104, 56 rounded-square letter tile) portrait / 6x2 landscape; ONE readout card of real numbers: BLOCKED (since install) | DATA USED (TrafficStats) | FILTERS age; notices only if relevant (old engine). No wallpaper, feed or sponsored tiles; no network at start.
**Downloads** (B2): rows 72: type tile 40, name 17 sp, meta in `monospace` 13 sp ("12.4 / 48 MB - 3.1 MB/s - 11 s left"), 4 dp progress under the row, Pause/Resume 56 + Cancel 56 on active rows; finished rows open on tap, overflow Share/Delete; failed rows show "FAILED" + Retry; long-press = multi-select bar; active section on top; >20 MB on a hotspot asks first.
**Find in page**: replaces the top row: [X 56][input][3/12][up 56][down 56]; Enter = next. **Long-press link/image**: bottom sheet (landscape: centred 360 dialog), header letter tile + host + 2-line URL, rows 56: new tab, private window, copy link, share, download (+ image: save, open, copy address, share; no Lens).
**Settings IA** (8 rows of 64 -> page; landscape two-pane 280 + rest): Privacy & Shields | Search & address bar | Data saver | Appearance (theme, text size, page dark mode, tab bar, toolbar position, style) | Downloads | Site settings | Filter lists | About & diagnostics.
**Private window**: "Hood" chrome (`#1E1530`, lilac marker `#CDB8FF`), permanent word chip "PRIVATE" + hood glyph in the field, NTP explainer, FLAG_SECURE (exists). Never colour alone (Brave's purple theme drew contrast complaints [S]).

## 6. Visual identity (recommended: CERE) and alternatives
Why a falcon palette is not enough: a 2026 catalogue of AI-template "tells" lists first-wave (purple gradients, one font, same radius+shadow everywhere, glass, fade-ups) AND second-wave looks (cream + terracotta = "the Claude palette", near-black + one neon, hairline broadsheet, tracked caps + monospace "template chrome") [V]. Its fix is process: derive choices from the product, write the direction down, audit against the tells. So:
- **Derived from the product**: hotspot -> real byte/block readouts in three places (NTP, Shields, Downloads); no animation -> explicit state words, fixed geometry, a loud "armed/under finger" marker; falcon -> one geometric cut and one yellow (the bird's cere/eye-ring/feet are yellow; kestrels hover and dive, males have a slate-blue head [V Wikipedia]); Shields is the product -> the yellow block in the chrome is always the Shield chip.
- **Self-audit**: no purple gradient, no serif, no cream/terracotta (avoid the rufous back colour as accent for that reason), caps+mono limited to readouts and section labels (<= 2 places per screen), chamfer used once per container, no glass. Honest caveat: dark mode with one accent is still the common pattern; kept because it is the most legible on a 170 ppi LCD in daylight.
- **Against stock Material (as shipped in Chromium: tab cards radius 24, toolbar radius 16, 18 dp close glyph in a 48 dp button [V])**: no pill/large radii, no tonal elevation or shadows, no ripples, no circular icon buttons or avatars, no FAB, mitred not rounded icons, square-ish cells that fill the whole 56/64 dp target.

Yellow on white is only 1.7:1, so on light surfaces it is ALWAYS a fill with ink content (never text, never a lone indicator) plus a glyph or word; the current accent `#D9480F` is 4.3:1 on white.
- **Shape**: bars 0 radius, controls 6, tiles/avatars 8 (rounded squares), sheets/cards/active tab/Shields panel 6 + 8 dp top-right chamfer (custom `ChamferDrawable`); 0 shadows, 0 elevation; separation by value steps + 2 dp rules.
- **Type** (system only; AOSP 10 `fonts.xml` has `sans-serif` Roboto 100/300/400/500/700/900, `sans-serif-condensed` 300-700, `monospace` Droid Sans Mono, serif Noto, `source-sans-pro` [V]; OEM build may differ [U]): Display 28 `sans-serif-medium`; Title 20 medium; Row 17 regular; Host 17 medium; Secondary 14; Meta 13 muted; Label 12 `sans-serif-condensed` bold caps (+0.04 em, headers/readout labels only); Readout numbers 22 condensed bold; live numbers (speed, ETA) 13 `monospace`. Nothing under 12 sp (14.4 dp at 1.2). Weights via `Typeface.create(Typeface, weight, italic)` (API 28) [V].
- **Icons**: 24 dp viewport, 2-unit padding (20 live), 2-unit stroke, butt caps, MITRE joins, 45 deg 3-unit chamfers instead of corner radii, filled twin for ON states (star, shield, desktop), only M/L/H/V/Z + circle arcs (<= 0.5 KB each), tinted at runtime. Contrast with Lucide (2 px stroke, ROUND joins/caps, 2 px radius [V]). Core 36: back fwd reload stop(x) plus menu(3 square dots) search lock lock-open warn shield shield-off star share find download history sliders(settings) hood(private) trash copy new-tab desktop text-size data-saver pause play folder file image video audio archive check chevrons(3) arrow-fill. Tab-count glyph = 24 dp square with the chamfer, count in condensed bold.
- **Feedback without animation** (`StateListDrawable`, `setEnterFadeDuration(0)`/`setExitFadeDuration(0)` [V]): chrome buttons/tiles/primary: pressed = yellow fill + ink glyph, selected = yellow fill, focused (keyboard/D-pad) = 2 dp ring in text colour inset, disabled = colour (never alpha); list rows: pressed = `bar` fill, selected = 4 dp yellow left bar + check glyph; toggles: ON = yellow track + ink word "ON", OFF = outline + "OFF".
- **Density**: 4 dp base, steps 4/8/12/16/24/32/48; gutters 16 (portrait) / 24 (landscape); rows 56 (1 line) / 72 (2 lines); section label row 40; sheet padding 16.
- **Alternatives**: **RUFOUS** - white/grey tonal surfaces, rufous `#C2410C` accent (5.2:1 on white), 10 dp rounded squares; closest to Brave (safe, familiar) but reads as a Brave/terracotta default. **STOOP** - dark-first `#0B1320`, ice `#7DD3FC` accent (11.2:1), 45 deg chamfers on every corner (HUD look); most distinctive, risks gamer/neon "dark signal" tell and eye strain. Recommendation: CERE.

## 7. Implementation consequences (framework Views)
1. `ui/Ui.kt`: replace `ripple()` (a `RippleDrawable`, which animates) with `Feedback.states(...)` returning cached `ConstantState` drawables; `Pal` becomes `Tokens` (+ style switch). Remove `elevation` on FindBar (4), SuggestionList (8), MenuPopup/ShieldsPanel (12): borders instead (shadows and fades are overdraw sources [V]).
2. Overdraw/RAM: window background = `bg`, containers without backgrounds, opaque bars, no `alpha` (the Back button uses `alpha = 0.38f`: use the disabled colour; Android's own example is grey text instead of translucent black [V]); zero bitmap assets (vectors, `GradientDrawable`, custom `onDraw`); favicons optional 32 px LRU 64 = ~256 KB [U]; one `Path` cached per `ChamferDrawable` in `onBoundsChange`.
3. Zero animation toolkit: `PopupWindow.setAnimationStyle(0)` (0 = no animation, -1 = default [V]), `Window.setWindowAnimations(0)` on own `Dialog`s (not `AlertDialog`, whose theme animates), theme `windowAnimationStyle` -> null style, `overridePendingTransition(0,0)`, `OVER_SCROLL_NEVER`, own `ListView.setSelector` (theme selectors are ripples), custom `Toggle` view (framework `Switch` animates its thumb [U]).
4. Touch targets: set `minimumWidth/Height` to 56/64 dp on the clickable view itself and draw a 24 dp glyph centred (`ImageView.ScaleType.CENTER`), as Android recommends [V]. Avoid `TouchDelegate` in the chrome: the ancestor must forward `onTouchEvent`, one delegate per parent view, and Accessibility Scanner only honours it on API 29+ [V/U]. Add a unit test that walks the view tree and fails on any clickable < 48 dp or any `RippleDrawable`.
5. Lists: `ListView`/`GridView` (no RecyclerView): current `TabSwitcher`, `ListPanel`, `SuggestionList` ignore `convertView` and inflate a row per bind [V code]; use a view holder, fixed row heights, 50-80 ms debounce on suggestion queries, SQLite on the IO executor.
6. Pressed state inside scroll containers is deferred by the tap timeout (~100 ms) [U]: override `shouldDelayChildPressedState()` to false in our list/grid containers if "instant" matters more than scroll-start flicker.
7. Font scale 1.2 (and up to 1.5): bars fixed in dp, rows `minHeight`, single-line ellipsis in chrome; test 1.0/1.2/1.5 x light/dark/private x both orientations on 600x973 @170.
8. Gecko vs WebView: all chrome is shared (`app/src/main`); keep the engine view a sibling of the chrome, overlays opaque and few (Gecko surface compositing cost is [U]).
9. Order of work: P1 tokens + Feedback + Shapes + Fonts + icons + Toggle + Sheet/Dialog bases (C1); P2 ChromeMode, top row, bottom bar, strip, typing mode (C2); P3 grid, menu, Shields, NTP, long-press, find, downloads (B2), settings, errors (C3); P4 screenshot review + owner A/B of styles (C4).
