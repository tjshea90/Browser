# FREEZE - the typing freeze (R6): ranked causes, fixes, detection + recovery, tests

Written 2026-11-11 by a research agent; no code was changed. NOTHING here was run on the tablet or an emulator (no KVM in this sandbox). Tags: **[V]** verified this session (primary source read, or the GeckoView 160 `classes.jar` disassembled with `javap -c`, dumps in the session scratchpad `gvdis/`); **[F]** user/forum report (anecdote); **[S]** only seen in a search snippet, page not opened; **[U]** inference or not verified.
Owner symptom (Brave): the screen stops updating while typing; it repaints only after switching apps and coming back.

## 1. Decisions

1. One symptom class: *the web layer stops presenting frames (or the UI thread stops serving them) while input still works.* An app switch cures it because Android destroys and re-creates the window and its SurfaceViews and re-runs focus + IME attach [U mechanism]. Chromium and Gecko both have the class. GeckoView does not make Kestrel G immune, and Kestrel G adds self-inflicted amplifiers (section 3). Keep GeckoView: the engine is not the reason to switch.
2. Gecko's vsync is the app's UI-thread Choreographer [V: `AndroidVsync implements Choreographer.FrameCallback`, set up on the main Looper] and extension messages arrive on the UI thread [V: `WebExtension$Listener` uses `registerUiThreadListener`]. Any UI-thread stall therefore freezes page painting AND typing echo. Today every sub-resource request costs UI-thread JSON + filter, and every blocked one a full toolbar refresh (3.1, 3.2).
3. P0 code: (a) answer the Shields bridge off the UI thread, batch its counters; (b) never detach GeckoView: one view stays attached, `setSession` swaps tabs, NTP/error become opaque overlays (Mozilla's `GeckoEngineView` keeps ONE `GeckoView` [V]); (c) coalesce and diff `updateUi()`.
4. P0 safety net, shipped FIRST so the next report carries evidence: UI-stall watchdog + GeckoView probes + 512-line ring buffer + Diagnostics screen + a one-tap "Refresh screen" menu item (= rungs R1+R2 of 5.2).
5. Recovery ladder (5.2): `setActive(false/true)` -> `GeckoView.requestNewSurface()` -> re-attach -> close + restore the session -> offer restart. Log-only for one alpha, then automatic with caps.
6. Hidden A/B switches for the tablet to judge (Diagnostics): TextureView backend, `adjustNothing` while the URL field is focused, autofill off, extensions process on. Owner test needing no code: Developer options "Disable HW overlays".
7. The cost of every UI-thread item below is UNMEASURED [U]. The first alpha must measure (heartbeat + FrameMetrics + Perfetto) before anything is tuned.

## 2. Ranked causes for the Brave symptom on this tablet, and what each means for GeckoView

| # | Cause (likelihood) | In a GeckoView app | Kestrel G today |
|---|---|---|---|
| 1 | **Surface / compositor / HWC desync (HIGH)**: the layer showing the page stops presenting or holds a dead Surface; the stale last frame stays; typing "works" but nothing repaints | Yes. ## 3. What can stall Kestrel G today (file:line, from reading the code)

1. `ShieldsBridge.onMessage` (ShieldsBridge.kt:29) runs on the UI thread for EVERY request [V]: `GeckoBundle -> String -> JSONObject`, `Shields.effective` (about 6 SharedPreferences reads + allocations, :56), `fs.check`, `Log.d` per block (:61), then `countBlocked -> blockedOnTab -> shieldCountChanged -> updateUi()` (:65-70, BrowserActivity.kt:844). Gecko holds the request until we answer.
2. `updateUi()` (BrowserActivity.kt:836) -> `Toolbar.bind` (Toolbar.kt:101): 2x `setImageResource`, `setColorFilter`, 2x `setText`, content descriptions, many `requestLayout()` - on EVERY progress tick (`onProgressChange`, TabDelegates.kt:132), title / location / back / forward change and every blocked request. No diff, no coalescing.
3. `attachContent()` (BrowserActivity.kt:338-355) runs `content.removeAllViews()` and re-adds GeckoView. Callers: `show`, `loadUrl` (:503, every address-bar navigation), `errorChanged`, `sessionGone`, `handleBack`, `onResume`, and `onNetworkChanged -> retry` (:827; fires on hotspot flaps, also while the user types). Detach = `GeckoDisplay.surfaceDestroyed -> syncPauseCompositor` + `maybeSetActive(false)` (-> `flushSessionState`, 10 s memory-pressure timer); attach = `syncResumeResizeCompositor` + `maybeSetActive(true)` [V bytecode]. It runs while the keyboard hides and `adjustResize` resizes the window: the race family of Bugs 1824083 / 1766127 / 1798714.
4. Two writers of session activity: we call `setActive` in `onResume` / `onStop` / `show` (:172, :184, :320, :324) while GeckoView already calls `maybeSetActive(true/false)` whenever its surface becomes valid / destroyed [V]. [U] A stuck "inactive but visible" state (no paint, input still delivered) would look exactly like the symptom.
5. `applyPrivacyFlags()` (:332) calls `window.setFlags/clearFlags(FLAG_SECURE)` inside every `show()`: a window relayout each time even when unchanged [U: may also recreate the SurfaceView surface].
6. `GeckoRuntime.create` + extension install are posted 600 ms after `onCreate` on the UI thread (:147-150); typing in the first seconds competes [U magnitude].
7. Typing path: `afterTextChanged -> onUrlText` queues `db.suggest` per keystroke on the single IO thread (BrowserActivity.kt:582-592; `LIKE '%q%'` scans, BrowserDb.kt:64-72), no debounce / cancel; results rebuild a WRAP_CONTENT ListView (new views + `RippleDrawable` per row, 8 dp elevation). It delays session saves and history writes more than it stalls the UI.
8. Latent: `newPopupSession` attaches after a fixed 60 ms (:437) although Gecko opens that session itself [U race]; the geckoapp manifest `configChanges` (:45) lacks uiMode / fontScale / density, so a dark-mode or font-scale change recreates the activity and closes every session.
9. No observability: `onKill` / `onCrash` are handled (TabDelegates.kt:142-143) but not recorded; no timeline of trim, memory, IME, focus or surface events.

## 4. Prevention rules

1. UI budget: no UI-thread task over 8 ms; no disk / SQLite / JSON / filter / network on it. Wrap `onMessage`, `updateUi`, `attachContent`, suggestion bind in `android.os.Trace.beginSection` so Perfetto shows who owns the thread.
2. Shields: `onMessage` creates the `GeckoResult` on the UI thread (listeners run on the creating thread's Looper; the class is `@AnyThread` [V]) and returns it at once; one `kestrel-shield` worker parses, decides and calls `complete("1"|"0")`. Counters are `AtomicInteger`s flushed to the UI at most every 250 ms. No `Log.d` per request.
3. One GeckoView, always attached: `releaseSession()` then `setSession(s)` to swap [V GeckoEngineView]; NTP / error / settings are opaque siblings above it toggled with `setVisibility`; never `removeAllViews()` on its parent, never INVISIBLE / GONE it (destroys the surface).
4. `updateUi()` = set a dirty bit + one `Choreographer.postFrameCallback`; `Toolbar.bind` compares with the last bound values and touches only what changed; `onProgressChange` updates the ProgressLine only (steps of 2 % or more).
5. Window: `FLAG_SECURE` only when the private state flips. Keep `adjustResize` for typing inside pages (Fenix's `HomeActivity` uses it [V]). While the URL field is focused use `SOFT_INPUT_ADJUST_NOTHING` + the opaque suggestion layer so the surface never resizes (agrees with research/UI_BENCHMARK.md "Typing mode"; set it before focus, restore after the IME hides).
6. Session activity has one owner: `setActive` only for tab switches and `onStop` / `onStart`; GeckoView's `maybeSetActive` covers surface-driven changes; log each call with the surface state.
7. Input: `geckoView.setAutofillEnabled(false)` (default true [V]; no logins are stored anyway); avoid focusable popups while the IME is up; after any dialog / PopupWindow dismissal run rung R0 (5.2) if a page editable had focus.
8. Typing path: debounce suggestions 100-150 ms, drop stale queries before they run, fixed-height list, reuse rows, no shadow; keep `SharedPreferences.apply()` off `onPause` / `onStop` paths (QueuedWork waits there); counters via the IO thread.
9. Memory: `setPriorityHint(PRIORITY_HIGH)` on the visible session only ("GeckoView will keep the session state as long as possible" [V]); log MemAvailable / `lowMemory` at every `onTrimMemory`; no filter-list compile while a tab loads.
10. Debug builds: `StrictMode.setThreadPolicy(ThreadPolicy.Builder().detectAll().penaltyLog().build())` plus a VM policy for leaked closables / SQLite / activities; wrap `GeckoEngine.runtime()` in `permitDiskReads` (GeckoView's own startup will be noisy [U]).
11. Long term: no per-request round trip at all (TASKS D1: verdicts inside the extension, or declarativeNetRequest) and re-decide `extensionsProcessEnabled` (cross-check research/ADBLOCK_ENGINE.md, GECKO_SPEED.md).

## 5. Detection and automatic recovery ("switch apps and back" without the owner)

**5.1 Probes.** Cheap; armed only while the activity is resumed with window focus; thresholds are constants in `core` so tests can scale them.

| Layer | Probe | Meaning |
|---|---|---|
| L0 UI thread | daemon thread posts a token to the main Looper every 500 ms; lag >= 700 ms = warn; >= 2 s = record `Looper.getMainLooper().thread.stackTrace` (top 12 frames) | main thread blocked: GC, binder, layout, sync compositor IPC |
| L0 jank | `Window.addOnFrameMetricsAvailableListener` (API 24): `INTENDED_VSYNC_TIMESTAMP != VSYNC_TIMESTAMP` or `UNKNOWN_DELAY_DURATION > 0` = UI thread late for vsync [V doc]; `TOTAL_DURATION` > 32 ms | jank counters per 10 s |
| L1 echo | subclass `GeckoView`, override `onCreateInputConnection`, wrap the result in `InputConnectionWrapper` (stamp `commitText` / `setComposingText` / `deleteSurroundingText` / `sendKeyEvent`, delegate everything incl. `getHandler`); install a `TextInputDelegate` that stamps `updateSelection` / `restartInput` / `showSoftInput` / `hideSoftInput` and forwards to the previous `session.textInput.delegate` (the default instance [V]) | key sent, no echo within 1.2 s = content / IPC stall or IME desync |
| L2 compositor | `session.compositorController.addDrawCallback{}` ONLY while armed (typing, touch, or 1.5 s after any resize / attach / visibility change); it switches on native layer-update notifications [V], per-frame cost unmeasured [U]; `ContentDelegate.onFirstComposite` / `onPaintStatusReset`; override `GeckoView.requestNewSurface()` to LOG Gecko's own recovery | echo present but no draw = compositor / surface stall; after a GeckoView size change expect a draw within 1.5 s |
| L3 window | FrameMetrics silent while our views invalidate (typing in the URL field) although L0 is healthy | HWUI render thread / BufferQueue stall; `Activity.recreate()` is the only app-level lever [U] |
| Timeline | `onResume/onPause/onStop`, `onWindowFocusChanged`, `onTopResumedActivityChanged` (API 29), `onMultiWindowModeChanged`, GeckoView `onAttachedToWindow/onDetachedFromWindow/onSizeChanged`, `onTrimMemory(level)`, `onKill/onCrash`; at each trim and stall: `ActivityManager.MemoryInfo`, MemAvailable from `/proc/meminfo`, `/proc/pressure/memory` if readable, live child processes (`:tab*`, `:gpu`, `:socket`), default IME (`Settings.Secure.DEFAULT_INPUT_METHOD`) | the facts needed to classify an owner report |

**5.2 Recovery ladder** (UI thread). Detector states: HEALTHY -> ARMED (key / touch / resize seen) -> SUSPECT(rung n) -> HEALTHY again on echo + draw. Every rung first checks the L0 heartbeat is healthy; R2+ log `begin` before and `end` after the call (they do sync compositor IPC, so a wedged compositor would hang the UI thread inside the call and the persisted log would show begin without end).

| Rung | Exact call | Cost | Emulates | Fires when |
|---|---|---|---|---|
| R0 | `session.setFocused(false); session.setFocused(true)`; `imm.restartInput(geckoView)`; if `!imm.isActive(geckoView)`: `geckoView.clearFocus(); geckoView.requestFocus()` (GeckoView's own Bug 1404111 repair) | ms | IME re-attach after a focus bounce | keys sent, no echo for 1.2 s; after a dialog / popup closes over an editable |
| R1 | `session.setActive(false); session.setActive(true)` [V: dispatches GeckoView:SetActive; false also runs `flushSessionState` and arms a 10 s `notifyMemoryPressure`, true cancels it and re-sends the keyboard height] | ms | engine-level `onStop/onResume` | armed, no draw for 1.2 s |
| R2 | `geckoView.requestNewSurface()` = posted `SurfaceView INVISIBLE -> VISIBLE`: fresh Surface, `surfaceDestroyed` (sync pause) + `surfaceChanged` (sync resume). GeckoView's comment: works on Android 5-13, posted to stay out of the current callback [V] | 50-300 ms flicker | the window-surface recreation of an app switch; the repair Gecko runs itself when a compositor resume fails (Bug 1824083) | R1 did not help within 1.5 s |
| R3 | `val s = geckoView.releaseSession(); content.removeView(geckoView); content.addView(geckoView); geckoView.setSession(s)` (or a new `GeckoView`; `setViewBackend(BACKEND_TEXTURE_VIEW)` goes before `setSession`) | 0.3-1 s | full view re-attach | R2 did not help |
| R4 | existing `sessionGone(tab, false)` path: `releaseSession(); close(); restoreState/loadUri` | 1-3 s + reload over the hotspot | content-process restart | R3 failed, or `onKill/onCrash` |
| R5 | menu "Restart Kestrel": save session, `finishAndRemoveTask()`, relaunch | seconds | app restart | two failed R4 within 2 min, user confirms |

Caps: >= 1.5 s between rungs, <= 4 rungs per incident, <= 3 incidents per 5 min, then stop and show a bar "Screen froze 3 times - open Diagnostics". An L0 stall cannot be repaired from inside (evidence only); prevention (section 4) is its fix. Ship manual "Refresh screen" (R1 then R2) in the very first alpha.

**5.3 Evidence the owner can send.** `RingLog(512)` of lines `+12.345s <layer> <event> <detail>`; the watchdog thread (never the UI thread) appends to `filesDir/freeze.log` (2 files x 64 KB) on a stall >= 2 s, on every rung, and on `onStop`. Diagnostics screen (TASKS A5): counters (stalls, rungs fired, kills / crashes, Gecko `requestNewSurface` calls), last 100 events, device facts (GeckoView version, RAM, IME, child processes, GPU process yes / no), "Copy report" + "Share" (ACTION_SEND text; no network, no telemetry). Optional "verbose engine log": `Bundle.putString("env0","MOZ_LOG=IMEHandler:5")` [V: `GeckoThread.getEnvFromExtras` reads env0..N; reaching it through `GeckoRuntimeSettings.Builder.extras` is [U]].

**5.4 Code plan.** Pure logic (state machine, thresholds, caps, ring buffer) in `core/src/main/kotlin/app/kestrel/core/health/{FreezeDetector,RingLog}.kt` with fake-clock tests in `core/src/test`; Android glue in `app/src/main/.../diag/`; Gecko probes + a `KestrelGeckoView` subclass in `geckoapp/src/main/.../GeckoHealth.kt`.

## 6. How to test it

**Emulator (Android 10 x86_64, software GL).** Boot takes about 185 s and the CPU is TCG-emulated [V scratchpad emu4.log], so absolute timings mean nothing: compare baseline vs fix, thresholds scalable by an instrumentation arg. It CAN show:
- (a) ladder + watchdog logic, and that every rung leaves a painted page (`adb exec-out screencap -p` before / after; a debug flag "pretend no draw" forces the ladder);
- (b) stall detection (debug broadcast that sleeps the main thread 2.5 s);
- (c) surface-churn counts per navigation (acceptance: zero GeckoView detaches over 20 navigations after P0 #3);
- (d) lifecycle: `adb shell input keyevent KEYCODE_HOME`, wait, `adb shell monkey -p app.kestrel.browser.gecko -c android.intent.category.LAUNCHER 1`;
- (e) memory: `adb shell am send-trim-memory app.kestrel.browser.gecko RUNNING_CRITICAL` [S: syntax from the AOSP change]; kill a `:tab` / `:gpu` child (`adb shell kill -9 <pid>`, needs `adb root` on an AOSP image [U]) to exercise `onKill` and GPU-process recovery;
- (f) hotspot flaps: `adb shell svc wifi disable; sleep 4; adb shell svc wifi enable` (drives `onNetworkChanged -> retry -> attachContent`);
- (g) `adb shell dumpsys gfxinfo app.kestrel.browser.gecko framestats` (+ `reset`) for jank %, p95 / p99; debug `StrictMode` log; a Perfetto trace (`adb shell perfetto -o /data/misc/perfetto-traces/k.pftrace -t 30s sched freq idle am wm gfx view input binder_driver dalvik res`, then `adb pull`; this category-list form on Android 10 is [U]) read in ui.perfetto.dev.

**Typing.** `adb shell input text` injects KEY events (`GeckoView.onKeyDown`, the `EditText` key path); it does NOT exercise the IME `InputConnection.commitText` path. For that use an AVD with `hw.keyboard=no` and `input tap` on soft keys, or a debug-only broadcast calling `geckoView.onCreateInputConnection(EditorInfo())?.commitText("a", 1)` at 15 Hz.

**Stress page** (`web-tests/freeze-stress.html`, served by `python3 -m http.server` + `adb reverse tcp:8000 tcp:8000`): an autofocused `<textarea>` logging `input` times; every 2 s 300 `fetch('/x?'+i,{cache:'no-store'})` + 100 `new Image().src='/ads/'+i+'.gif'` (matches EasyList path rules) + 30 `<iframe>`s; a `requestAnimationFrame` loop mutating the DOM; then 10 chars/s for 60 s. Record key-to-echo delta, heartbeat max lag, FrameMetrics jank %, `ShieldsBridge` messages/s. Gate: p95 echo < 250 ms and no heartbeat lag >= 700 ms (relative on the emulator); `updateUi` calls <= 60/s; zero UI-thread time in `onMessage`.

**Only the real tablet can tell**: Mali-G52 / MTK HWC behaviour (A/B: "Disable HW overlays", TextureView), the real IME, lmkd / PSI / eMMC thrash (`getprop | grep lmk`, `/proc/pressure/memory`), thermals, true frame times, whether a `:gpu` process runs, hotspot behaviour, whether Kestrel G freezes at all. Owner protocol: normal use with the Diagnostics log on; when it freezes, tap "Refresh screen" and note which rung cured it (R1 vs R2 separates "session state" from "surface").
