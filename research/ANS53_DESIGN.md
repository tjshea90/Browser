# ANS53 (owner message 53, 2026-11-16 04:59Z, on alpha56): design and findings

## What the owner asked (verbatim in INBOX.md and TASKS.md ANS53a-h)
a never autoplay anywhere; b no video data (download or buffering) until play is pressed, posters only; c controls instantly (zero delay) on tap and on the next tap; d a quality setting in the player controls for as many videos as possible (resolution, bit rate, frames a second); e the download button was lit on Home for a page left (bug); f Kestrel's own player opened portrait stretched, then forced landscape, no way back (bug); g feedback: Kestrel's own player was very smooth and noticeably smoother than the page's player.

## Gecko facts (read in dom/media/autoplay/AutoplayPolicy.cpp and HTMLMediaElement.cpp, gecko-dev master; the file is dom/media/autoplay/, not dom/media/)
- `media.autoplay.default`: ALLOWED (0), BLOCKED (1) = an audible start needs a gesture, a muted one is allowed, BLOCKED_ALL (5) = nothing starts without a gesture, muted or not.
- `media.autoplay.blocking_policy`: 0 sticky (any user activation of the top window earlier allows autoplay for good), 1 transient (the play() call must be within the transient activation, about 5 s after a gesture, or the element was "blessed" by an earlier play() inside a gesture), 2 input depth (only while handling the input).
- GeckoView (`media.geckoview.autoplay.request` true): the engine asks the app (content permission AUTOPLAY_INAUDIBLE / AUTOPLAY_AUDIBLE) ONLY when the blocking model has not allowed the start already. A DENY from the app does NOT stop a document that has sticky user activation (policy 0): after the owner's first tap anywhere on a page its videos may start by themselves. This is why the engine's own rule is not enough and the page-side gate exists.
- `preload`: no attribute = `media.preload.default` (METADATA, i.e. bytes are fetched), `preload=auto` = `media.preload.auto` (ENOUGH), `preload=metadata` fetches metadata and stops, `preload=none` creates no channel until play() (PlayInternal resumes a suspended load). A blocked autoplay leaves the load suspended. The poster is a separate image load.
- Nothing in Gecko fetches media for a paused `preload=none` video. MSE / HLS / DASH players (hls.js, video.js VHS, Shaka, dash.js, YouTube) fetch with XHR and `fetch` by themselves and are NOT governed by any media preference.

## Design: three layers, the strict one is the page-side gate
1. Engine preferences (GeckoEngine.applyVideo): `media.autoplay.default` 5, `media.preload.default` 1 (none), `media.preload.auto` 1 (none); the permission delegate answers DENY to both autoplay requests, always (the Settings row "Muted videos may start by themselves" is gone; the preference key stays so old backups restore).
2. Page gate `kestrel-shields/gate-main.js` (world MAIN, every frame, document_start, same declaration as guard-main.js): a media element is CLOSED until the person presses it. While closed: `preload` is forced to none (the page's own value is remembered and given back when it opens), `autoplay` is not applied, a `blob:` (MediaSource) `src` is HELD (the player then waits for `sourceopen`, so hls.js / VHS / Shaka / dash.js / YouTube fetch no segment at all; the manifest is small and goes), `load()` is held, and `play()` without a transient user activation is refused with NotAllowedError (what Gecko's autoplay rule would say) so a document with sticky activation cannot start it either. It OPENS (held things are applied, in order) when: (a) `play()` is called with `navigator.userActivation.isActive`; (b) a trusted tap lands inside the picture of a closed element (covers custom play overlays and the engine's own controls, and players that wait for `canplay` before calling play(), which would deadlock otherwise); (c) Kestrel's own controls (videobar.js, player.js, the one-press-plays assist, turn.js's resume) dispatch `__kst_gate_v1` on the element before they call play(): a content script's own play() does not pass through the page's wrapper. `srcObject` streams (camera, calls) are never held.
3. Request level backstop: none (a hold on XHR would only make the player's own timeouts fire). Poster images, thumbnails and manifests load as always.
- A Settings switch ("Videos start only when I press play", ON) is the escape hatch for a site that breaks; the app sends it as flag 1024 of the guard answer; until the answer arrives the gate is closed (the owner's rule is the default).
- Counters (held, opened by play() / press / Kestrel's controls, source assignments held, plays refused) go to Diagnostics as "Videos start only when pressed".
- Known limits: a frame without our content script (about:blank frames the page makes, `match_about_blank` is false for content.js) keeps the gate closed by default and opens by press; a player whose play button is OUTSIDE the picture and which waits for canplay before play() would need a second press (the switch is off for such a site).

## ANS53c: zero delay
The 300 ms double-tap wait was the delay; on a busy page the page script's message (page thread -> extension -> app) came on top (the tablet's page script is late by seconds). Now: TapMachine toggles at once (no wait, no fade); the activity sees the tap on the glass itself and answers at once (PlayerController.appTap), the page's copy of the same tap is matched by the touch time and dropped, a tap on one of the page's own buttons (`vtap pg:1`) puts the controls back. Double tap on a side still seeks (second tap within 300 ms); the middle has no double-tap meaning.

## ANS53f: Kestrel's own player
Cause: `FullscreenTurn.onEnter(MODE_AUTO ...)` turned a wide film sideways (SENSOR_LANDSCAPE one-time turn) at the first picture and the activity never let it go; the SurfaceView filled the screen until the first size arrived (stretching). Now: `FullscreenTurner(MODE_FOLLOW)` (full sensor: follows the tablet also with Android's rotation lock on), a rotate button in the controls (one-time turn, handed back when the tablet is held that way), the surface is a 1x1 point until the picture's shape is known and then letterboxed.

## ANS53d: quality
Kestrel's own player: a Quality button (shown when the stream offers two or more pictures) lists every picture (Media3 tracks: picture class, frames a second, bit rate) + Automatic; the pick is a track override and is remembered (Prefs.nativeMaxH: the next film starts at no more than that). `core/media/QualityLabel` words the rows. For films played in the page: a Quality button in the page's full-screen controls lists the rungs the app knows from the HLS playlist and hands the film over to Kestrel's own player at that rung (same time), see TASKS ANS53d.2.

## ANS53e: the badge
`refreshDownloadButton`, `onDownload` and `VideoFlow.available` ignored `showHome`: the Home button puts a screen over a page that stays alive underneath, its media list stayed. All three use `homeShown(t)` now (a new page start still clears the list: `pageStarted -> clearTab`).
