## Addendum A (2026-11-15): second independent review of the video bar scripts (vfind.js / videobar.js / content.js / background.js), 0 critical, 3 major, 4 moderate, 5 minor
The reviewer ran the repo scripts read-only in headless Chromium (repros t1-t10) and found: RW1 a video that is not in the element stack under the finger counted by rectangle alone (a link / button over a decorative film gave the Save sheet or the bar); RW2 full screen of a web component's HOST left the bar in the host's light DOM (0 x 0: this is why the owner saw no Kestrel controls in full screen on Yahoo); RW3 `ownControls` stopped at the first 1500 candidates of the document (1700 links before a Video.js player gave a bar over the page's own controls); RW4 panel and Save sheet could both open when the frame round trip took over 400 ms; RW5 the tap window (600 ms) was longer than the engine's long press (500 ms); RW6 the frame relay matched by size only (two frames of one size); RW7 a page could name a layer `data-kestrel-bar` to switch the menus off and fake pointer events cancelled real taps; RW8 work on the touch path; RW9-RW12 smaller. All fixed in alpha49 with their own tests (`web-tests/videobar.test.js`, 25 tests); rows RW1-RW12 in TASKS.md. One more note of the reviewer: the tests cannot exercise CLOSED shadow roots, and their srcdoc frames get scripts that Firefox would skip (`match_about_blank: false`): the lab pages use real addresses for frames (`/blank`).

## Addendum B (2026-11-15): independent review of the alpha49 Kotlin change set (FSB1 / ROT1 / SND1b), 0 critical, 2 major, 3 minor
RA1 a closed / hibernated / replaced session never says "deactivated", so `videoPlaying` and the `MediaSession` object stayed behind (checked with javap on the GeckoView 160 AAR: `pause()` / `play()` dispatch an event and do nothing on a dead session, no throw): a turn covered a page with no video and "paused" a dead session, `silenceStrays` counted a stray pause on every run. Fixed in the `Tab.session` setter. RA2 on Android 10 the decor pads itself and consumes the insets before the root's listener, so the new "system bars" note read zero while both bars were showing; the layout itself was right. `checkBars` reads `decorView.rootWindowInsets` now. RA3 timers cancelled in onDestroy. RA4 the turn state machine got a pure core class and 12 tests (one of them found that a second turn during a turn was ignored once the video had been paused). The reviewer's "checked, nothing found" list is worth keeping: keyboard / urlTyping on API 29 and 30+, nothing else reads the root padding, the cover takes no touch and is hidden from accessibility, no stuck cover or timer path, private tabs log only a tab id.
