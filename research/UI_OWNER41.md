# Owner message 41 (2026-11-15): the panel that would not close, a close X, a tab left on Home, the Private box, the launch picture (alpha46)
ASCII only. What was wrong, what was done, what was proven and what was NOT. Panel details: research/MINI_NAV.md (MN1 / MN2).

## HM1 - a tab left on the Home screen comes back as the Home screen
Owner: "I just pressed the home button to put a tab on the home screen, switched tabs to a different tab, then came back ... but instead of the home screen it loaded the site I was on before the home screen."
Cause: `BrowserActivity.show(tab)` ran `tab.showHome = false` whenever the front tab changed ("coming back to a tab shows its page, not the Home overlay"), a line from the very first Home overlay. The tab switcher card, the saved session (AQ1) and the tab's own state already said "Home"; only the switch cleared it.
Fix: the line is gone. `show()` no longer touches `showHome`; Back, a new address, the Home screen's own search and the Home button keep their meaning. The page stays alive under the Home screen (as when Home is pressed).
Proof: OwnerRulesTest `aTabThatWasLeftOnTheHomeScreenComesBackAsTheHomeScreen` (reads the source: Gecko module has no unit tests). EMULATOR 2026-11-15: lab page in a tab, Home button, tab grid (the card says Home), another tab, tab grid, the Home card: the Home screen (screenshot). NOT run: on the tablet; a restart of the app on a Home tab is AQ1's (alpha33) and was not rerun.

## PT1 - no Private box without private tabs
Owner: "when I close all private tabs, make the private tab box at the top of the tab selector disappear, because there are no more private tabs, then automatically default to the regular "tabs" page."
Change: `TabGrid.refresh()` hides the Private segment while there is no private tab and, if the Private list was showing, switches to the regular list (and tells the activity: `paneChanged(false)`, screenshots are allowed again). A private tab is opened from the menu ("New private tab"), so nothing is lost by hiding the box; when one exists the box is back (an open grid does not jump to it).
Proof: TabGridPrivateBoxTest (4). EMULATOR: no private tab -> only "Tabs 6" at the top; a private tab from the menu -> "Tabs 6" and "Private 1" (violet pane); its X on the card -> the Private box gone and the regular Tabs page in front (screenshots). Note: a debug build needs `adb shell setprop debug.kestrel.nosecure 1` BEFORE the app starts, or the secure window flag turns every private screenshot black.

## SP1 - the launch picture is the app's own symbol, and it glows once
Owner: "when Kestrel first loads, it shows a shield icon. Instead of this shield, make it match the symbol from the app drawer. If possible, give it a very quick lightweight animation ... very fast so I don't have to wait."
What the owner saw: the starting window (drawable/launch_window.xml: black with a flat shield, drawn by Android before the app's process runs). On Android 10 that window cannot animate (it is a drawable the system draws once), so:
(1) launch_window.xml now draws `ic_launcher_foreground` (the shield with the falcon of the icon in the app drawer) at 148 dp; launch_shield.xml is gone.
(2) in the first frame of the app `ui/LaunchLogo` (added by BrowserActivity.onCreate when savedInstanceState == null) draws the same symbol at the same place over the same black, glows once in the neon blue and fades while the black clears and the screen comes up under it: 380 ms in all (core `session/LaunchAnim`: cover, logo alpha, halo, scale curves; LaunchAnimTest 6). It keeps its OWN clock (the owner runs Android with animations off, a system animator would jump to its end), starts at its first draw, takes no touch, tells accessibility nothing, one gradient allocated once, nothing waits for it (the screen under it is already built and starts as before).
(3) the Home screen's brand mark next to "KESTREL" is the same symbol (the private Home keeps a small violet shield); the Shields chip in the address bar stays a shield (it IS the Shields button).
Two bugs found by the emulator proof and fixed: the symbol sat 13 px higher in the app than in the launch window (this view starts under the status bar; it now centres on the window); and the fade left the Home screen's brand mark invisible, because a vector drawable shares its alpha with every drawable made from the same resource (`mutate()`; LaunchLogoTest guards it).
Proof: LaunchAnimTest, LaunchLogoTest (6). EMULATOR 2026-11-15 with a DEBUG-only slow motion (`adb shell setprop debug.kestrel.logostretch 45` stretches the flourish 45 times; a release build always plays 380 ms): the launch window shows the symbol; the app's first frame shows it in the same place; later frames show the Home screen coming up with the glowing symbol fading over it; the last frame has no leftover overlay and a bright brand mark (screenshots). NOT run: at real speed (the emulator's cold start is 20+ s and each screenshot takes seconds), on the tablet (a first start on the tablet takes seconds; the flourish only adds 0.38 s of fade over a screen that is already visible).
Not done: "spreading wings" (the symbol is one drawable; the glow was the cheap, fast choice the owner offered).
