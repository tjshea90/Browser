# The app closing on www.ally.com (AX2, 2026-11-14)

**Symptom (owner message 38):** "Kestrel keeps crashing while loading this page. The entire app closes." https://www.ally.com/help/invest/dividend-reinvestment/

**Cause, reproduced on the emulator.** GeckoView's Android passkey code (`org.mozilla.geckoview.WebAuthnTokenManager`, `org.mozilla.gecko.util.WebAuthnUtils`) is written against Google Play services: its static initializer (`<clinit>`, line 58) builds an array of `com.google.android.gms.fido.fido2.api.common.Algorithm`. This app has no Google services (it must not: no GMS dependency) and neither has the tablet. A page that only ASKS about passkeys - a bank's login widget calling `PublicKeyCredential.isUserVerifyingPlatformAuthenticatorAvailable()` or `navigator.credentials.get({publicKey: ...})` - makes the engine's native code call that Java class, the class cannot load, `NoClassDefFoundError` is thrown inside the app process and nothing catches it: the whole app closes. Only secure pages (https, or http://localhost) have the API, so a plain http lab page never showed it.
Logcat on the emulator, before the fix: `java.lang.NoClassDefFoundError: Failed resolution of: [Lcom/google/android/gms/fido/fido2/api/common/Algorithm;  at org.mozilla.geckoview.WebAuthnTokenManager.<clinit>(WebAuthnTokenManager.java:58)`, process gone. Only these two GeckoView classes mention `com/google/android/gms` (checked in the 160 AAR).

**Fix.** `security.webauth.webauthn = false` in `geckoapp/src/main/assets/gecko-prefs.txt` (config version 8; the name exists in `libxul.so`, `tools/check-gecko-prefs.sh` passes; read back in Diagnostics "Engine prefs"). The page then sees no `PublicKeyCredential` and no `navigator.credentials` and offers the password. After the fix on the same emulator: `PublicKeyCredential is undefined`, the app stays up, no `NoClassDefFoundError`. Guard: `CrashNoteTest.thePasskeyApiStaysOffInTheEngineConfiguration`.

**Not known:** that the owner's crash was exactly this (the page's raw HTML could not be fetched here; the WebFetch answer shows an ordinary help article with a login link). It is the only way found in this engine for a page to close the app by merely loading, it matches "keeps crashing on this page", and it reproduces. If the app still closes on that page, the new crash note tells why.

**Crash note (so a crash is never a mystery again).** `app/diag/CrashNote.kt`: a default uncaught-exception handler writes `files/last-crash.txt` (exception with causes, thread, version, last 30 Health events), then the previous handler runs as before. Diagnostics shows `EARLIER CRASH of this app` (kept 7 days) and `Engine crash reports on disk` (the engine's own `.extra` files: process type, MozCrashReason, time, memory). A native crash that leaves nothing behind (Android killing the app for memory) is still invisible: Android 10 has no exit-reason API.

**Lab:** `http://localhost:8001/wa` (`tools/sitelab/adlab.py`, adb reverse) asks the three passkey questions at load; before the fix the app died, after it the page reports `PublicKeyCredential is undefined`.
