## Checked and fine (read, so nobody re-audits it)
- **Controls view cost** (`PlayerControlsView`): nothing is drawn while the controls are hidden and the film plays; `update()` invalidates only when a DRAWN unit changed (whole second, whole pixel); the buffering ring is a 20 fps dirty-rect; no `setLayerType`, no view alpha (no offscreen buffers); the seek bar seeks once, on finger-up (`:489-496`).
- **Tick rate and allocations:** both players tick at 1 Hz hidden / 4 Hz shown; per tick a few small objects (`Sample`, `View`, strings): no GC pressure on a 128 MB heap. `Health.log` is a StringBuilder and a ring (no I/O).
- **Surface:** SurfaceView, zero copy, not TextureView; full screen is two layers (video, window) with the bars hidden; a rotation is a resize of one SurfaceView (`configChanges` handled, `fit()` only changes layout params when the size changed). Inline is Gecko surface + media-overlay surface + window (plus bars); the overlay follows the page by `translationX/Y` from the compositor's scroll callback (SurfaceView position is applied on the RenderThread since API 28 [est]). HWC layer budget of the MT8168 not verified.
- **Neon glow** holds still while a film plays (`BrowserActivity.kt:2912`, `inlineChanged`), stepped at 10 Hz with cached layers otherwise; the glow does not run in the full-screen activity at all.
- **Load control vs ABR:** 15/30 s with 16 MiB and the 10 s back buffer is consistent with `AdaptiveTrackSelection` defaults (up at >= 10 s buffered, down below 25 s, retain 25 s) at 2.5 Mbit/s (40 s x 0.31 MB/s = 12.5 MB < 16 MiB); 10 s timeouts, the shared meter and `WAKE_MODE_NETWORK` (held only while `playWhenReady`) are ANS60's and not re-argued.
- **Track selection:** Media3's viewport rule keeps 1080p out on a 1024x600 panel (the smallest rung that is at least viewport-sized is 720p), plus `applyCap` 720 for full screen and a 60 fps limit; frame-rate matching is a no-op at API 29 (fixed 60 Hz panel) and helps on Android 16. With the 720p cap the HW VP9 limit (1080p30) is not reached, so the software fallback decoders are not reached for ladder films [est].
- **`onVideoDecoderInitialized` builds `MediaCodecList(ALL_CODECS)` on the main thread** (`NativePlayerActivity.kt:195`, `InlinePlayer.kt:168`): looked at and left alone; the framework builds its codec list once per process (static) and Media3 has already done that on the playback thread before the callback, so the constructor is cheap [est, AOSP].
- **Volume gesture** calls `setStreamVolume` only when the index changes (`VideoLevels.kt:26`).
- **Injected scripts idle during playback:** `players.js` and `youtube.js` watch only class attributes until an ad class shows (250 ms loop only during an ad, at most 15 s); `turn.js` interval only during a turn; `gate-main.js` and `codec-main.js` have no timers or polling (verdicts cached, 200 entries); `quality.js` / `quality-main.js` act only on a pick; `videobar.js` interval (250 ms place + `timeupdate` render) only while its bar is up (about 4 s); `seekbar.js` is passive listeners; `vfind.js` is bounded and does nothing until asked.
- **Extension plumbing:** `hlscap` filter is narrow (.m3u8 URLs only, 512 KB cap, byte-for-byte fallback) and Kestrel's own player never passes through it; the media sniffer keeps `.ts/.m4s` out (`SEGMENT`), dedupes, caps 300 per tab and floors at 100 KB; the early-look and verify fetches are a few KB, at most 6 per page, never while the page loads.
- **Page `player.js` report rate:** 1 Hz idle, 4 Hz while the controls show, about 300 bytes, 3 hops: fine apart from PB6.
- **Diagnostics machinery:** `Health` watchdog (500 ms beat), the FrameMetrics listener on its own thread and `CpuMeter` (5 s, five file reads on the IO lane) are negligible [est].
- **Seek:** default EXACT kept (ANS60 decision); the 10 s back buffer makes back skips instant; double-tap bursts accumulate against the player's masked position.
- **Gecko prefs for page video:** the `media.cache_*` values, AV1 off, press-to-play, the page codec policy and the HLS size cap are as decided (VIDEO_AUDIT, GECKO_SPEED, VIDEO_ACCELERATION). No `media.*` / `gfx.*` change is proposed: no pref name can be checked here (no GeckoView AAR) and no tablet number points at one.
- **Not a bug, by design:** page film paused for up to 2.2-7 s on a rotation (`TurnSettle`), the glow limit for muted video (RX3-S1 known limit).

## Not verified (what would settle it)
1. **PB1:** whether Media3 throws the load error while buffered film remains (my memory says it throws as soon as the retry count is exceeded). Test: pull the network for 20 s with 25 s buffered and watch the `error` Health line time against `ahead`.
2. **PB7:** the VPN -> NETWORK_TYPE_OTHER mapping and the default estimate for OTHER. Test: first `onBandwidthEstimate` and first picture bitrate with the VPN on.
3. **PB2:** the loader thread name prefix ("ExoPlayer:Loader:...") and that Android's HttpURLConnection honours the second `Proxy.NO_PROXY` entry on a refused CONNECT. Test on the emulator with Courier and the throttled lab server.
4. **HLS start:** which rung ExoPlayer loads first while preparing a master playlist (the first listed or the lowest). If it is the first listed, a master that lists 1080p first downloads a 1080p chunk before ABR acts (about 1.5-4 s at 4 Mbit/s). Also `HlsMediaSource.Factory.setAllowChunklessPreparation(true)` (masters with CODECS attributes become ready without waiting for a segment) was not tried. Test: log the first `onDownstreamFormatChanged` bitrate against the master's order on a lab ladder.
5. **Decoder count:** a late hand-over starts ExoPlayer while Gecko's decoder for the page's film may still be alive; MTK limits concurrent HW decoders. The Health "decoder ... (software)" line is the check; none seen in the repo.
6. **CA store:** HttpURLConnection uses the system store frozen at July 2021; Gecko uses its own newer roots. A film host whose chain needs a newer root fails in the player (before the first picture the page's own player takes over, so only a second host mid-film would hit the PB1 path).
7. **HWC layers** of the MT8168 for the inline view (Gecko surface, overlay surface, window, bars) and the one-frame lag of the overlay behind a fast fling: unprovable without the tablet (already listed in ANS55).
8. **No tablet numbers:** the repo holds no "Kestrel's own player" stats lines from the tablet after alpha61; every [est] above needs the owner's next Diagnostics (stalls, link estimate, picture bitrate, buffered ahead, dropped).
